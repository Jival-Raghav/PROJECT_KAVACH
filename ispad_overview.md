## Detailed Feature Reference (For In-Depth Slide Content)

Use this section if Claude or the presenter needs deeper technical specifics for any individual slide or speaker note.

### 1. Ingestion & Smart Schema Mapping
- **Input Formats**: CSV, JSON, JSONL, Apache Parquet.
- **Profiling Engine**: Automatically computes row counts, memory footprint, column data types, missing value ratios, and cardinality.
- **Mapping Confidence**: Returns `exact` (1.0), `synonym` (0.85), `heuristic` (0.60–0.75), or `llm` (0.50–0.90) with interactive visual badges.
- **DSL Functions**:
  - `split(col, delim, idx)`
  - `strip(col)`
  - `lower(col)` / `upper(col)`
  - `regex_replace(col, pattern, repl)`
  - `coalesce(col1, col2, ...)`
  - `derive_field(formula)`
- **Persistent Feedback**: Saves user corrections to the SQLite `mapping_feedback` table; incorporates past decisions into subsequent heuristic mappings.

### 2. Identity Resolution & Entity Clustering
- **Blocking Strategies**: Domain-based, first-three-letters Soundex, and departmental blocking.
- **Matching Algorithms**: Jaro-Winkler string distance on usernames and full names; Jaccard index on historical entitlement sets.
- **Clustering Algorithm**: Disjoint-Set Connected Components (Union-Find) with path compression. Assigns confidence scores (`HIGH`, `MEDIUM`, `LOW`).
- **Identity Types**:
  - `human_employee`: Matched against HR database.
  - `contractor`: Matched with expiration dates or contractor tags.
  - `service_account`: High event volume, automated tasks, non-interactive shell.
  - `bot`: CI/CD runners, deployment agents.
  - `shared_account`: Multiple concurrent IP addresses across geographical regions.

### 3. Generalized Anomaly Detection Core
- **13 Canonical Features**:
  1. `after_hours_ratio`: Ratio of events outside 08:00–18:00 local time.
  2. `weekend_ratio`: Activity on Saturday / Sunday.
  3. `sensitivity_ratio`: Interactions with crown-jewel assets.
  4. `distinct_systems`: Count of unique systems touched.
  5. `inactivity_days`: Days elapsed since previous activity.
  6. `history_zscore`: Rolling 30-day volume deviation.
  7. `failed_login_ratio`: Proportion of failed authentication events.
  8. `new_system_access_rate`: Rate of first-seen system interactions.
  9. `impossible_travel_flag`: Geolocation distance velocity exceeding 800 km/h or cross-subnet hopping < 2 minutes.
  10. `burst_access_count`: Maximum event volume in any rolling 1-hour window.
  11. `privileged_action_ratio`: Proportion of admin, root, or sudo commands.
  12. `unused_entitlement_ratio`: Dormant permissions held with zero usage.
  13. `entitlement_vs_peer_median`: Entitlement count relative to peer median.
- **Dynamic Feature Injection**: Custom fields marked `role: feature` in the unified schema automatically enter the feature matrix.
- **Self-Calibrating Isolation Forest**: Automatically calculates contamination $\nu$ via knee detection on the raw decision score distribution.
- **Separation of Duties (SoD)**: Enforces 7 rules in `config/sod.yaml` across both conflicting entitlements and conflicting runtime actions.

### 4. Adversarial Dual-LLM Adjudication
- **The Prosecutor Prompt**: Formulates accusations with specific event timestamps, policy violation IDs, and threat vectors.
- **The Devil's Advocate Prompt**: Uses an explicit investigative tool-calling workflow to cross-reference:
  - `get_user_tickets(user_id)`: Active approved Jira / ServiceNow tickets.
  - `get_oncall_schedule(user_id)`: PagerDuty / Opsgenie on-call rotations.
  - `get_leave_records(user_id)`: Approved HR PTO/vacation calendar.
  - `get_peer_baseline(user_id)`: Departmental activity distribution.
- **The Adjudicator Prompt**: Reconciles conflicting arguments; outputs structured JSON with `adjudicated_verdict` (`DISMISS`, `DOWNGRADE`, `MAINTAIN`, `ESCALATE`), `confidence_score` (0.0–1.0), `rationale`, and `mitigating_factors`.

### 5. Identity Graph & Attack Path Analytics
- **Graph Schema**: Directed Multi-Graph $G = (V, E)$ where $V \in \{\text{User}, \text{Account}, \text{Entitlement}, \text{Resource}, \text{Session}\}$ and $E \in \{\text{HAS\_ACCOUNT}, \text{GRANTS}, \text{ACCESSED}, \text{CAN\_ESCALATE}, \text{MEMBER\_OF}\}$.
- **Shortest Attack Path**: Dijkstra search with edge weights inversely proportional to privilege level (easier hops have lower weights).
- **Blast Radius Reachability**: Forward breadth-first search (BFS) determining all reachable crown-jewel nodes from any identity node.
- **What-If Simulation**: Computes difference $\Delta R = R_{\text{current}} - R_{\text{simulated}}$ after hypothetical edge deletion.

### 6. Posture & Compliance Engine
- **Frameworks Audited**:
  - **SOC 2 Type II**: CC6.1, CC6.2, CC6.3.
  - **ISO/IEC 27001:2022**: A.9.2.1, A.9.2.3, A.9.2.6, A.9.4.2.
  - **NIST CSF v2.0**: PR.AC-1, PR.AC-4, PR.AC-6, PR.DS-5.
- **Control Checks**: Audits 15 distinct rules including stale admin accounts (>30d inactive), unowned service accounts, unreviewed elevated privileges, and SoD conflicts.
- **Audit Export**: Generates timestamped, tamper-evident audit packages in JSON and Markdown formats.

### 7. AI Security & Non-Human Identity (NHI) Governance
- **Threat Model**: Covers OWASP Top 10 for LLMs:
  - *T1: Direct & Indirect Prompt Injection*
  - *T2: Metric & Severity Forgery*
  - *T3: Tool Hijacking & Argument Poisoning*
  - *T4: Markdown Image Exfiltration & SSRF*
  - *T5: Unicode BiDi & Zero-Width Obfuscation*
  - *T6: Non-Human Identity Sprawl*
- **Defense Suite**:
  - `backend/security/sanitize.py`: Unicode NFKC, zero-width stripping, markdown url/image removal.
  - `backend/security/injection_detect.py`: Regex and token pattern matching for system delimiters and prompt overrides.
  - `backend/security/pseudonymize.py`: Deterministic token mapping (`USER_XXXX`, `IP_XXXX`) and random cryptographic nonces.
  - `backend/security/invariance.py`: Verdict floor enforcement preventing malicious demotions.
  - `backend/security/nhi.py`: Dedicated auditor for API keys, service accounts, and machine identities lacking human custodians.

## Anticipated Judge / Investor Q&A (Defense Guide)

### Q1: *"What if the Devil's Advocate hallucinates a benign excuse for a real attacker?"*
> **Answer**:  
> *"We designed the Devil's Advocate with strict factual grounding. It cannot invent context; it is forced to call deterministic tools (`get_user_tickets`, `get_oncall_schedule`, `get_leave_records`). If no approved ticket or on-call shift exists in the database, the Devil's Advocate explicitly returns a `doubt_score` of 0.0. Furthermore, our **Verdict Invariance Check** enforces a hard rule: if any indicators of tampering or true attack invariants exist, the model is physically forbidden from demoting severity."*

### Q2: *"How does this scale to an enterprise with 50,000 employees and millions of daily events?"*
> **Answer**:  
> *"Our pipeline is built for high-throughput enterprise scale. Ingestion and feature extraction happen in Python using vectorized NumPy/Pandas and PyArrow. Anomaly pre-filtering is performed by an ultra-fast Isolation Forest in under 1 second. Only the top anomalous outliers (e.g., top 1-2%) are sent to the LLM adjudication layer. Furthermore, our identity resolution engine uses candidate blocking to reduce pairwise comparisons from $O(n^2)$ down to $O(n)$, and our LLM gateway features deterministic disk-caching to eliminate redundant inferences."*

### Q3: *"Can an attacker bypass your prompt injection defense using novel zero-day techniques?"*
