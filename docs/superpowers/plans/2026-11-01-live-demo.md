# Kavach Live Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Point Kavach at a local 10–50 GB FortiGate log and watch every view fill in and get revised, cycle by cycle, while the file is still being processed. This is PRD bonus B-5.

**Architecture:** A `LiveJob` thread streams the file (raw or `.gz`) into Parquet parts. It writes atomically and saves a resumable checkpoint after each part. A loop re-runs the existing post-ingest pipeline (`analyse_run`, factored out of `run_killchain`) over the parts written so far. Cycles never overlap. Each cycle maps incidents onto stable numbers through a registry, writes every output file atomically, bumps a `generation` counter and appends a change-feed entry. The frontend sends the selected `run_id` on every call and polls live status. When `generation` changes, each mounted page re-fetches.

**Tech Stack:** Python 3.12, DuckDB, PyArrow/Parquet, FastAPI, pytest; React 18 + Vite, lucide-react. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-01-live-demo-design.md`

## Global Constraints

- Work on branch `feat/live-demo`. Commits carry only the user's name: **no `Co-Authored-By` or any Claude attribution line**.
- No damage to the current setup: the firex run, `python -m killchain.cli run`, `bench`, and all existing tests (173 at plan time) behave exactly as before. Run `pytest -q` at the end of every task.
- Live mode never writes to the `firex` run directory. `run_id` `firex` is rejected by live start.
- The firex batch path keeps its 1..N incident numbering. Stable numbering applies only when a registry path is passed.
- No new Python or npm dependencies. Gzip comes from the stdlib `gzip`.
- The new UI reuses the existing CSS variables (`--surface`, `--border`, `--text-*`, `--accent*`, `--c-critical*`, `--c-review*`, `--c-normal*`, `--c-info*`, `--radius`), existing classes (`card`, `btn-primary`, `btn-ghost`, `chip`, `badge-*`, `kc-*`) and lucide icons. New CSS goes in one `/* Live mode */` block at the end of `frontend/src/styles.css`, built only from those variables, and must look right in both light and dark themes.
- Every JSON or Parquet output that the API or DuckDB may read while a cycle runs is written atomically: to a temp name in the same directory, then `os.replace`.
- Rules must still contain no dataset IOCs. Do not touch `config/detection_rules/`.
- Ruff: line length 100, rules E/F/W.

## Review Focus

1. **Start with a bad path** (missing, a directory, unreadable, empty string) → HTTP 400 with "File not found: <path>" or "File is not readable: <path>". No run directory is created. *(Task 6: `test_start_rejects_bad_paths`.)*
2. **API restarted mid-run** → `/api/live/status` reports `interrupted`, not a stale `processing`. Starting the same `run_id` resumes with no duplicate lines. *(Task 5: `test_stop_and_resume_equals_uninterrupted`; Task 6: `test_status_reports_interrupted_without_job`.)*
3. **Incident open while it merges or is withdrawn** → the page follows to the surviving number, or shows "This incident was withdrawn after more data arrived." It never shows a raw error. *(Task 6: `test_merged_and_withdrawn_ids_return_detail`; Task 7: manual check.)*
4. **A file small enough to fit in one part** → exactly one cycle, then status `complete` with `generation == 1`. *(Task 5: `test_single_part_file_completes`.)*
5. **DuckDB globbing a part that is still being written** → never possible, because parts are written as `*.parquet.tmp` and renamed. *(Task 4: `test_no_partial_parts_visible`.)*

### Task 2: Stable incident numbers (registry)

**Files:**
- Create: `backend/killchain/registry.py`, `tests/test_kc_registry.py`
- Modify: `backend/killchain/pipeline.py` (`analyse_run` gains `registry_path`)

**Interfaces:**
- Consumes: `models.Incident` (`incident_id`, `detections[].detection_id`, `first_seen`), `atomic.write_json_atomic`.
- Produces:
  - `registry.load_registry(path: Path) -> dict`: `{"next": 1, "numbers": {}}` when the file is missing. Shape: `{"next": int, "numbers": {"<n>": {"status": "active"|"merged"|"withdrawn", "detections": [str], "merged_into": int | None}}}`.
  - `registry.save_registry(path: Path, reg: dict) -> None` (atomic).
  - `registry.renumber(incidents: list[Incident], reg: dict) -> dict`: sets each `inc.incident_id` in place and updates `reg`. Returns `{"new": [int], "merged": {old: new}, "withdrawn": [int]}` for this cycle.
  - `registry.resolve(reg: dict, number: int) -> dict | None`: `{"merged_into": final_active_n}`, following chains; or `{"withdrawn": True}`; or `None` if the number is active or unknown.
  - `analyse_run(..., registry_path: Path | None = None)`: when it is given, load → `renumber` right after `rank(correlate(...))`, before any per-incident output is built → save. It also adds `meta["renumber"]` (the dict returned by `renumber`). When it is `None`, nothing changes.

Assignment algorithm (the tests pin this behaviour):
```
old = {n: set(e["detections"]) for n, e in reg["numbers"].items() if e["status"] == "active"}
overlap(i, n) = len(dets(i) & old[n])
for n in sorted(old):                                   # lowest number chooses first → merges keep the lower number
    takers = [i for i unassigned if overlap(i, n) > 0]
    if takers: assign n to max(takers, key=(overlap, -first_seen_ts))
for each still-unassigned incident: assign reg["next"]; reg["next"] += 1; record in "new"
for each old n not assigned:
    best = the incident with max overlap(i, n) > 0, if any
    best → status "merged", merged_into = best.incident_id ; none → status "withdrawn"
every assigned number → status "active", detections = its current detection ids
```

### Task 4: Streaming reader with checkpoints

**Files:**
- Create: `backend/killchain/live.py` (reader half), `tests/test_kc_live_stream.py`

**Interfaces:**
- Consumes: `parse.parse_line`, `parse.FIELDS`, `ingest.SCHEMA`, `atomic.write_json_atomic`.
- Produces:
  - `live.STATE_FILE = "live_state.json"`, `live.read_state(run_dir: Path) -> dict | None`, `live.save_state(run_dir: Path, state: dict) -> None` (atomic).
  - `live.new_state(path: Path) -> dict` → `{"path": str(resolved), "status": "processing", "gz": bool, "parts": 0, "lines_read": 0, "lines_parsed": 0, "lines_skipped": 0, "next_offset": 0, "bytes_read": 0, "bytes_total": <file size>, "ingest_done": False, "generation": 0, "cycle_seconds": None, "last_cycle_at": None, "started_at": <UTC ISO>, "finished_at": None, "error": None}`. `gz` is detected from the first two bytes `b"\x1f\x8b"`, not from the file name.
  - `live.stream_to_parts(path: Path, run_dir: Path, state: dict, *, batch_size: int = 200_000, stop: threading.Event | None = None, on_part: Callable[[dict], None] | None = None) -> dict`:
    - Resumes from `state`. A raw file seeks to `next_offset`. A gz file opens fresh and skips `lines_read` lines.
    - `line_no` continues from `lines_read`, numbered exactly like `ingest_log`: 1-based, counting every line read.
    - A line without a trailing `\n` at EOF, or one that fails to decode, is skipped and counted.
    - Each full batch is written to `events/part-NNNNN.parquet.tmp` (zstd, `SCHEMA`) and `os.replace`d to `.parquet`. After each part the reader updates `parts`, the line counters, `next_offset` (raw: the byte position after the batch's last line; gz: unused), `bytes_read` (raw: same as `next_offset`; gz: the underlying compressed file's `tell()`), then calls `save_state` and `on_part(state)`.
    - At EOF it flushes the remaining batch as a part, sets `ingest_done=True`, `bytes_read=bytes_total`, and saves.
    - If `stop` is set, it returns before writing a partial batch, leaving the last checkpoint intact.

### Task 5: `LiveJob`: cycles, final cycle, stop and resume

**Files:**
- Modify: `backend/killchain/live.py` (job half)
- Create: `tests/test_kc_live_job.py`

**Interfaces:**
- Consumes: `stream_to_parts`, `read_state`/`save_state`/`new_state`, `store.list_parts`, `store.write_clock_stalls`, `pipeline.analyse_run(..., parts=, registry_path=, seconds=, meta_extra=)`, `pipeline.load_run`, `changes.diff_cycle`/`append_change`.
- Produces:
  - `class LiveJob(run_dir: Path, path: Path, rules_dir: Path, *, assets_path: Path | None = None, batch_size: int = 200_000, poll_seconds: float = 0.5, on_cycle: Callable[[dict], None] | None = None)`.
    - `run() -> dict` blocks and returns the final state.
    - `start() -> None` runs `run()` in a daemon thread.
    - `stop() -> None` and `is_alive() -> bool`.
    - `state` holds the latest state dict.
    - `__init__` raises `ValueError("Run <id> was started on <old path>")` if an existing state's `path` differs from `path`.
  - `run()` behaviour:
    - Load the existing state or create one with `new_state`. Set `status="processing"` and clear `error`.
    - Start the reader thread (`stream_to_parts`).
    - Loop: when `len(list_parts) > parts_at_last_cycle`, run a **cycle**. Once the reader has finished and the last cycle has covered every part, stop.
    - Cycle:
      1. `parts = list_parts(run_dir)`.
      2. `write_clock_stalls(run_dir, parts)`.
      3. `prev = load_run(run_dir)`.
      4. `meta = analyse_run(run_dir, rules_dir, assets_path=…, parts=parts, registry_path=run_dir/"incident_registry.json", seconds={"ingest": reader_elapsed}, meta_extra={"log_path": str(path), "ingest": {counters from state}})`.
      5. `cur = load_run(run_dir)`.
      6. `entry = diff_cycle(prev, cur, meta["renumber"], cycle=k, generation=state["generation"] + 1, pct=bytes_read / bytes_total)` and `append_change`.
      7. Update `generation`, `cycle_seconds`, `last_cycle_at` → `save_state` → `on_cycle(entry)`.
    - End state:
      - Reader finished and all parts analysed → `status="complete"`, `finished_at` set.
      - `stop()` called → reader and loop exit after the current cycle, `status="stopped"`.
      - Any exception → `status="error"`, `error=str(exc)`, then re-raise inside `run()`. When started via `start()` the thread only records the error.
  - Cycles never overlap. Each cycle runs in the job thread; the reader runs in its own thread.

- Produces (router `APIRouter(prefix="/api", tags=["Live"])`; run dir = `KILLCHAIN_DATA_DIR/runs/<run_id>`; `run_id` uses the same pattern `^[A-Za-z0-9_-]{1,64}$`):
  - `POST /api/live/start`, body `{"path": str (max 4096), "run_id": str | null}`.
    - `run_id` defaults to `live-%Y%m%d-%H%M%S` (UTC).
    - 400 `"The firex run cannot be used for live mode"` if `run_id == "firex"`.
    - 400 `"File not found: <path>"` if the path (after `expanduser`) is not a regular file.
    - 400 `"File is not readable: <path>"` if `os.access` fails.

  - `POST /api/live/stop?run_id=` → `{"status": "stopping"}`; 404 if no alive job for that run.
